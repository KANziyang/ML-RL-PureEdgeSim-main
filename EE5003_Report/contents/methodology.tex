\section{Methodology}
\label{sec:methodology}

\subsection{MAPPO Framework Overview}
\label{subsec:mappo-overview}

The proposed scheduler follows the centralized training with decentralized execution (CTDE) paradigm. During training, a centralized critic observes a global simulator state and evaluates device actions under system-wide congestion, load imbalance, and PRB utilization. During execution, each device acts independently using only its own local observation and the feasible-destination mask. This separation matches the target edge-computing scenario well: rich global information is available during simulation and offline learning, whereas online deployment should avoid a centralized decision bottleneck.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.92\textwidth]{figures/mappo_ctde_framework.png}
    \caption{Overall MAPPO framework under centralized training and decentralized execution.}
    \label{fig:mappo-ctde-framework}
\end{figure}

Each task-generating device is treated as one agent. When a new task reaches the orchestrator, the corresponding agent receives its observation, selects an execution destination, and, if the task is offloaded, selects a PRB allocation level. The environment then resolves the action, executes the task in PureEdgeSim, and returns a task-level transition to the learner. The final framework used in this report incorporates three design choices to improve coordination quality. First, the actor uses a learnable agent embedding so that different devices need not share one undifferentiated latent representation. Second, the centralized critic augments the 27-dimensional global state with recent joint-decision telemetry summarizing destination and PRB selections over the latest decision window. Third, training is fallback-aware: if the environment replaces a requested destination with a feasible fallback, the transition is penalized in the reward and excluded from PPO updates so that policy optimization remains on-policy.

The use of a single dual-head actor differs from two common alternatives in the literature. Sun and He \cite{sun2023hdmappo} adopt a hierarchical MAPPO design in which a high-level agent selects the offloading destination and a low-level agent determines the offloading ratio. Although such decomposition reduces the action space handled by each policy, it also introduces extra coordination complexity between the two levels. In contrast, the actor in this report performs destination selection and PRB selection within one forward pass, which keeps the learning pipeline simpler and avoids additional hierarchical reward shaping. Ke et al. \cite{ke2022demadrl} instead use fully decentralized DDQN agents without a centralized critic. That design removes centralized training overhead, but it also sacrifices the coordination benefit of shared system-level information. The CTDE formulation adopted here provides a more suitable balance for dense edge-cloud scheduling: execution remains decentralized, while training can still exploit global information to learn cooperative behaviour.

\subsection{Observation and State Design}
\label{subsec:observation-state}

The observation and critic-state design follows the implementation of the decision-support module \texttt{DeviceAgentDecisionSupport}. At each decision event, agent \(i\) receives the local observation
\begin{align}
o_i = \left(x_i, D_i, m_i\right),
\end{align}
where \(x_i \in \R^{13}\) is the 13-dimensional agent observation (\texttt{agentObs}), \(D_i \in \R^{N_d \times 11}\) is the destination-feature matrix (\texttt{destFeatures}), and \(m_i \in \{0,1\}^{N_d}\) is the destination-feasibility mask (\texttt{destMask}). Candidate destinations are ordered deterministically as local execution first, followed by edge data centers sorted by data-center identifier, and finally cloud destinations sorted by identifier. This fixed ordering ensures that every destination index has a stable semantic meaning across episodes.

The vector \(x_i\) contains three categories of local information. The first five dimensions describe the current task demand through task length, deadline, request size, result size, and container size. Dimensions 5--8 summarize the source-device state, including CPU utilization, battery level, running-task count, and the MIPS of the best local VM. Dimensions 9--12 provide network and temporal context through the number of reachable edge destinations, global PRB availability, simulation progress, and the maximum PRB fraction currently affordable for the task. \Tabref{tab:agent-observation-features} lists the 13 fields and their meanings.

All 13 dimensions are normalized before being sent to the actor. Task length, deadline, request size, result size, and container size are divided by their corresponding global maxima and clipped to \([0,1]\). CPU utilization, battery level, PRB ratios, and simulation progress are also clipped to \([0,1]\). Running-task counts are normalized by the maximum VM count per node and clipped to \([0,2]\). If no feasible local VM exists, \texttt{sourceLocalVmMipsNorm} is set to \(0.0\).

The destination mask \(m_i\) expands the feasibility test into an explicit action constraint. For destination \(j\),
\begin{align}
m_{i,j} =
\begin{cases}
1, & \text{if destination \(j\) has a feasible VM and, for offloaded destinations,} \\
   & \text{network admission is feasible}, \\
0, & \text{otherwise}.
\end{cases}
\end{align}
In the actor, this mask suppresses invalid destination logits before sampling. The policy therefore learns over the valid action region directly, rather than sampling infeasible destinations and being penalized only after execution.

For PPO, the critic input is the base global state
\begin{align}
s_{\mathrm{base}} \in \R^{27},
\end{align}
which is built by \texttt{fillGlobalState()}. The first 13 dimensions are an exact copy of the active agent's local observation \(x_i\). The remaining 14 dimensions are aggregated system statistics that summarize source-device load and energy, edge-side load dispersion, cloud utilization, active-task intensity, and global PRB usage. \Tabref{tab:global-state-features} lists the full composition of this base state.

For MAPPO, the critic receives an augmented state in which the 27-dimensional base state is extended with recent decision telemetry:
\begin{align}
s_{\mathrm{aug}} = \left[s_{\mathrm{base}}; h^{\mathrm{dest}}; h^{\mathrm{prb}}\right]
\in \R^{27 + N_d + 8},
\end{align}
where \(h^{\mathrm{dest}} \in \R^{N_d}\) is the normalized histogram of destination selections over the latest 200 decisions and \(h^{\mathrm{prb}} \in \R^{8}\) is the normalized histogram of PRB-bin selections over the latest 200 offloading decisions for which PRB allocation is actually applied. These telemetry terms are appended by \texttt{appendTelemetryToState()} and provide the critic with a compact summary of recent multi-agent coordination patterns. Under the default topology with one local option, four edge data centers, and one cloud destination, \(N_d = 6\), so the MAPPO critic input dimension becomes \(27 + 6 + 8 = 41\).

\subsection{Action Space Design}
\label{subsec:action-space}

At each decision step, agent \(i\) produces a composite action consisting of a destination selection and a PRB allocation level:
\begin{align}
a_i = \left(a_i^{\mathrm{dest}},\; a_i^{\mathrm{prb}}\right)
\in \{0, \dots, N_d - 1\} \times \{0, \dots, 7\}.
\end{align}
The two heads are sampled sequentially within a single forward pass: the destination head is evaluated first, and its output conditions the PRB head.

\paragraph{Destination head.}
The destination head selects one element from the ordered candidate list defined in \Secref{subsec:observation-state}: index~0 corresponds to local execution, indices \(1\) through \(N_d{-}2\) correspond to edge data centers sorted by identifier, and the last index corresponds to the cloud. Before sampling, the destination logits are masked by the feasibility vector \(m_i\) so that destinations with no available VM or no network admissibility receive \(-\infty\) and are never selected. Under the default topology, \(N_d = 6\).

\paragraph{PRB head.}
The PRB head selects one of eight discrete bins. Each bin specifies a ratio \(\rho_k\) of the per-task PRB cap \(B_{\max}\):
\begin{align}
\rho \in \{0.02,\; 0.05,\; 0.10,\; 0.20,\; 0.40,\; 0.60,\; 0.80,\; 1.00\},
\end{align}
and the integer block reservation is computed as
\begin{align}
b_k = \max\!\left(1,\; \left\lfloor \rho_k \cdot B_{\max} \right\rfloor\right).
\label{eq:prb-mapping}
\end{align}
Under the default configuration where \(B_{\max} = \lfloor 0.01 \times 5000 \rfloor = 50\), the eight bins map to \(\{1, 2, 5, 10, 20, 30, 40, 50\}\) blocks respectively. \Tabref{tab:prb-bin-mapping} lists the complete mapping.

\paragraph{Local-execution coupling.}
If the selected destination is local execution (\(a_i^{\mathrm{dest}} = 0\)), no wireless upload is required and the PRB reservation is forced to zero regardless of the PRB head output. In the policy, the log-probability and entropy contributions of the PRB head are also set to zero for local actions, so that the gradient signal is not distorted by an irrelevant bandwidth decision.

\paragraph{Destination fallback.}
Although destination masking prevents most invalid selections, a runtime fallback rule is retained for robustness against transient state changes between observation construction and action execution. If the sampled destination turns out to be infeasible at execution time---for example, because the target device has moved out of coverage during the intervening network delay---the environment replaces it with the feasible destination that has the shortest estimated completion time. The transition records both the originally requested action and the actually executed action, and the fallback event is signaled through a dedicated flag. As described in \Secref{subsec:training-algorithm}, fallback transitions are excluded from the PPO update buffer and penalized in the reward to discourage the policy from relying on environment-side corrections.

\subsubsection{TurnActor (MAPPO Actor)}

The MAPPO actor is implemented as a \texttt{TurnActor} with four stages: agent encoding, destination encoding, destination selection, and PRB selection.

\paragraph{Agent encoding.}
Each agent identifier is mapped to a learnable 16-dimensional embedding \(e_i\). The embedding is concatenated with the 13-dimensional agent observation to form a 29-dimensional input, which is then passed through a two-layer MLP with hidden size 128 and \(\tanh\) activations:
\begin{align}
h_i = f_{\theta}^{\mathrm{agent}}\!\left([x_i ;\, e_i]\right) \in \R^{128}.
\end{align}
The embedding table can be resized at runtime when the number of task-generating devices changes: new rows are initialized by cycling over existing embeddings, so that every new agent starts with a reasonable representation without retraining.

\paragraph{Destination encoding.}
Each candidate destination feature vector \(d_{i,j} \in \R^{11}\) is concatenated with the agent hidden state \(h_i\) and encoded by a shared destination MLP, again two layers with hidden size 128 and \(\tanh\) activations:
\begin{align}
u_{i,j} = f_{\theta}^{\mathrm{dest}}\!\left([d_{i,j} ;\, h_i]\right) \in \R^{128}.
\end{align}
Because \(h_i\) is broadcast across all \(N_d\) destinations, the destination encoder jointly conditions on both the candidate's properties and the requesting agent's context.

\paragraph{Destination head.}
A linear projection scores every encoded candidate, and the feasibility mask \(m_i\) suppresses infeasible destinations before sampling:
\begin{align}
\ell_{i,j}^{\mathrm{dest}} &= w_{\mathrm{dest}}^\top u_{i,j} + b_{\mathrm{dest}}, \\
\pi_{\theta}^{\mathrm{dest}}(j \mid o_i) &=
\mathrm{Softmax}\!\left(\mathrm{Mask}\!\left(\ell_{i,j}^{\mathrm{dest}},\, m_i\right)\right),
\end{align}
where \(\mathrm{Mask}\) sets logits of infeasible destinations to \(-10^{9}\). As a safety fallback, if no destination is feasible the mask is bypassed entirely so that the policy can still produce a valid sample.

\paragraph{PRB head.}
The PRB head is conditioned on the selected destination. The hidden vector of the chosen destination is concatenated with the agent hidden state and passed through a two-layer MLP:
\begin{align}
\ell_i^{\mathrm{prb}} &= f_{\theta}^{\mathrm{prb}}\!\left([h_i ;\, u_{i,a_i^{\mathrm{dest}}}]\right), \\
\pi_{\theta}^{\mathrm{prb}}(k \mid o_i, a_i^{\mathrm{dest}}) &=
\mathrm{Softmax}\!\left(\ell_i^{\mathrm{prb}}\right).
\end{align}
This destination-conditioned design is important because the desirable PRB level differs substantially between a nearby edge node and the more distant cloud tier. The total action log-probability used for PPO updates is the sum of the two heads:
\begin{align}
\log \pi_{\theta}(a_i \mid o_i) = \log \pi_{\theta}^{\mathrm{dest}}(a_i^{\mathrm{dest}} \mid o_i)
+ \log \pi_{\theta}^{\mathrm{prb}}(a_i^{\mathrm{prb}} \mid o_i, a_i^{\mathrm{dest}}),
\end{align}
with the PRB term zeroed out when local execution is selected, as described in \Secref{subsec:action-space}.

\subsubsection{CentralCritic (MAPPO Critic)}

The centralized critic maps the augmented global state to a scalar value estimate:
\begin{align}
V_{\phi}(s_{\mathrm{aug}}) = f_{\phi}^{\mathrm{critic}}(s_{\mathrm{aug}}).
\end{align}
The network is a three-layer MLP with two 256-unit hidden layers and \(\tanh\) activations, corresponding to the tuple \((41, 256, 256, 1)\) under the default 6-destination topology. Because the augmented state includes both instantaneous system statistics and recent decision-distribution telemetry, the critic can evaluate each action against not only the current load and PRB conditions but also the recent coordination behaviour of the agent population. This information asymmetry between actor and critic is the core of the CTDE paradigm: the critic exploits privileged global context during training to provide a more coordination-aware baseline, while the actor retains a purely local interface suitable for decentralized deployment.

\subsubsection{PPO Baseline}

The PPO baseline reuses the same destination encoder, destination head, and PRB head, but differs from MAPPO in two respects. First, the actor removes the learnable agent embedding, so the agent encoder receives only the raw 13-dimensional observation, corresponding to the tuple \((13, 128, 128)\). All devices therefore share one undifferentiated policy without explicit identity modelling. Second, the critic receives the base 27-dimensional global state rather than the telemetry-augmented 41-dimensional state, so its architecture follows the tuple \((27, 256, 256, 1)\) and has no visibility into recent joint-decision patterns. The comparison between PPO and MAPPO therefore isolates two factors: whether device identity is explicitly modelled in the actor, and whether the critic observes recent multi-agent coordination statistics.

\subsection{Reward Function Design}
\label{subsec:reward-function}

The environment returns one scalar reward after each task has been fully resolved:
\begin{align}
R_t =
\begin{cases}
-5.0, & \text{if the task fails}, \\
5.0 - \ell_t - 2.0\, e_t - 1.5\, n_t - p_t^{\mathrm{fb}}, & \text{if the task succeeds}.
\end{cases}
\label{eq:reward}
\end{align}
The four success-side terms are defined as
\begin{align}
\ell_t &= \mathrm{clip}\!\left(\frac{T_t}{T_t^{\max}},\, 0,\, 2\right), \\
e_t &= \mathrm{clip}\!\left(\frac{E_t - \mu_t}{\sqrt{\sigma_t^2 + 10^{-8}}},\, -2,\, 2\right), \\
n_t &= \mathrm{clip}\!\left(\frac{B_t}{\max(B_{\max}, 1)},\, 0,\, 1\right), \\
p_t^{\mathrm{fb}} &=
\begin{cases}
1.5, & \text{if destination fallback is triggered}, \\
0, & \text{otherwise},
\end{cases}
\end{align}
where \(T_t\) is the realized end-to-end task latency, \(T_t^{\max}\) is the task deadline, \(E_t\) is the total task energy reported by the simulator, \(B_t\) is the requested PRB reservation, and \(B_{\max}\) is the per-task PRB cap determined by the current system configuration.

This reward is designed to align policy optimization with the QoS objective of the system. In the present edge-cloud setting, QoS is reflected most directly by whether a task finishes successfully and whether it finishes within a small fraction of its latency budget. For that reason, task failure receives the strongest negative signal, while successful completion starts from a positive base reward and is then discounted according to the quality of the realized service. The reward therefore does not merely ask the agent to offload somewhere feasible; it pushes the policy toward decisions that improve completion reliability and reduce end-to-end delay, which are the two most immediate manifestations of user-perceived QoS in this workload.

The remaining terms are included because QoS in a congested mobile edge system is not determined by latency alone. The latency term \(\ell_t\) directly penalizes schedules that consume too much of the deadline budget. The energy term \(e_t\) is not a QoS metric in isolation, but it acts as a service-sustainability term: repeatedly choosing energy-expensive actions increases device stress and can degrade long-run service continuity, so the reward discourages such behaviour. In the implementation, \(\mu_t\) and \(\sigma_t^2\) are updated by exponential moving averages with smoothing factor \(\alpha = 0.01\), allowing this penalty to adapt online to the operating regime. The network term \(n_t\) penalizes aggressive PRB reservations, which helps prevent the policy from improving one task's delay at the expense of wider wireless congestion and degraded QoS for subsequent tasks. Finally, the fallback penalty \(p_t^{\mathrm{fb}}\) discourages decisions that are not robustly executable in the actual system state. Taken together, these terms make the reward QoS-oriented in a strict sense: it prioritizes successful and timely task completion directly, while using energy, PRB, and fallback penalties to suppress myopic actions that would otherwise erode overall service quality.

\subsection{Training Algorithm}
\label{subsec:training-algorithm}

Policy optimization follows the clipped PPO framework \cite{schulman2017ppo}. For transition \(t\), the policy ratio is
\begin{align}
\rho_t(\theta) =
\frac{\pi_{\theta}(a_t \mid o_t)}{\pi_{\theta_{\mathrm{old}}}(a_t \mid o_t)},
\end{align}
and the actor is optimized with the standard clipped surrogate
\begin{align}
L^{\mathrm{clip}}(\theta) =
\E_t \left[
\min \left(
\rho_t(\theta)\hat{A}_t,\,
\mathrm{clip}(\rho_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t
\right)
\right].
\end{align}
The critic is trained to regress the return through a mean-squared error objective,
\begin{align}
L^{\mathrm{value}}(\phi) = \E_t \left[\left(V_{\phi}(s_t) - G_t\right)^2\right].
\end{align}
In practice, the actor and critic are updated with separate Adam optimizers, and the actor objective includes entropy regularization to maintain exploration during early training.

For the finalized experiments reported here, the return is defined at the event level rather than through long-horizon bootstrapping:
\begin{align}
G_t &= r_t, \\
\hat{A}_t &= r_t - V_{\phi}(s_t).
\end{align}
The resulting advantages are normalized within each update minibatch. This immediate-return design is intentional. In the present simulator, each transition corresponds to a completed task-offloading decision whose outcome is directly observable once the task finishes. Treating each decision as a one-step event therefore matches the underlying interaction structure and avoids injecting additional variance from unnecessary multi-step credit assignment.

Another important implementation choice concerns destination fallback. If the environment replaces the requested destination with a feasible fallback destination at execution time, that transition is counted in the episode statistics but excluded from the PPO update buffer. Otherwise, the likelihood ratio would be formed from an action that was modified by the environment rather than executed exactly as sampled by the policy. For retained transitions, the stored log-probability is recomputed from the original action emitted by Python, not from the post-resolution destination actually executed in the simulator. This treatment keeps the optimization as close as possible to the on-policy assumption underlying PPO.

The entropy coefficient is linearly annealed from 0.02 to 0.002, promoting broad exploration in the early episodes and sharper decisions after the policy begins to stabilize. The main hyperparameters are listed in \Tabref{tab:training-hyperparameters}. These settings are consistent with stable PPO practice in cooperative multi-agent learning \cite{yu2022surprising}, especially the relatively conservative clipping range \(\epsilon = 0.1\) and the use of a centralized critic that supplements local observations with global coordination context.

The runtime configuration still exposes a nominal \(\gamma = 0.99\), but the reported runs use the immediate-return update above, so no discounted multi-step bootstrapping enters the final optimization.

Algorithmically, one training episode proceeds as follows.
\begin{enumerate}
    \item Java launches one 30-minute PureEdgeSim episode and exposes the MARL interface through \texttt{RLEnvServer}.
    \item Whenever a task reaches the orchestrator, the active device sends its masked observation to the Python learner.
    \item Python samples a destination action and, when offloading is chosen, a PRB action; the environment then executes the decision and returns the task-level transition.
    \item After the episode ends, values and advantages are computed from the collected transitions, and PPO updates the actor and critic for four epochs.
    \item The resulting checkpoints are reused for offline inference and for the multi-seed evaluation reported in Chapter~5.
\end{enumerate}

Overall, the training procedure preserves decentralized execution at deployment time while still exploiting centralized information during learning, enabling the policy to internalize congestion, contention, and cross-device coupling without introducing a centralized online controller.
